## 🔴 KRITIS — Keamanan & Risiko Data Loss

### 1. Path Traversal — Server-Side Write (Tanpa Validasi Path)

**File:** `server.ts` — baris 254–281, 283–336, 205–229

Endpoint berikut menerima `folder_path` dari body request tanpa validasi apa pun:

- `POST /api/save-chapter` (line 254)
- `POST /api/export-novel` (line 283)
- `POST /api/config` (line 242)

Kode terkait:
```ts
let targetFolder = folder_path || config.global_storage_path;
if (!path.isAbsolute(targetFolder)) {
  targetFolder = path.join(process.cwd(), targetFolder);
}
```

**Risiko:** Penyerang bisa menulis file ke sembarang lokasi filesystem:
- `folder_path: "../../etc/cron.d/malicious"` → menulis ke `/etc/cron.d/`
- `folder_path: "C:\\Windows\\Temp\\evil"` → menulis ke system32
- `folder_path: "../../../home/user/.ssh/authorized_keys"` → menimpa SSH key

**Dampak:** Full filesystem write access dari user yang terautikasi (atau tanpa autentikasi sama sekali).

**Rekomendasi:** Validasi path dengan `path.resolve()` + `path.relative()` check agar path tetap di dalam direktori yang diizinkan.

---

### 2. API Key Tersimpan dalam Plaintext & Dikirim ke Client

**File:** `server.ts` — baris 211–213, 238–239
**File:** `src/App.tsx` — baris 56–63

`config.json` menyimpan API key dalam plaintext:
```json
{
  "gemini_api_key": "",
  "openrouter_api_key": ""
}
```

Endpoint `GET /api/config` (line 237–239) mengirim seluruh config — termasuk API keys — kembali ke client. Client kemudian menyimpannya di `localStorage`:
```ts
localStorage.setItem('novel_translator_ai_config', JSON.stringify(newConfig));
```

**Risiko:** Siapapun yang memiliki akses ke file system (`config.json`) atau browser storage (`localStorage`) bisa membaca API key Gemini dan OpenRouter. API key bisa digunakan untuk:
- Mengirim request ke OpenRouter atas nama pemilik (biaya menggunung)
- Mengakses Gemini API dengan quota korban

**Rekomendasi:** Jangan pernah kirim API key ke client. Simpan hanya di server, dan gunakan server-side proxy untuk memanggil AI API.

---

### 3. Server Bind ke 0.0.0.0 (Semua Network Interfaces)

**File:** `server.ts` — baris 571

```ts
app.listen(PORT, '0.0.0.0', () => {
  console.log(`[Novel Translator Server] Listening on http://localhost:${PORT}`);
});
```

**Risiko:** Server mendengarkan di semua antarmuka jaringan (termasuk ethernet/WiFi publik), bukan hanya `127.0.0.1`. Jika deployment tanpa reverse proxy yang tepat, server terpapar langsung ke internet.

**Rekomendasi:** Bind ke `127.0.0.1` kecuali ada alasan spesifik untuk eksposur eksternal.

---

### 4. Tidak Ada Autentikasi/Authorization pada API

**File:** `server.ts` — semua endpoint

Semua endpoint API tidak memiliki autentikasi apapun:
- `GET /api/health`
- `GET /api/config`
- `POST /api/config`
- `POST /api/save-chapter`
- `POST /api/export-novel`
- `POST /api/translate`
- `POST /api/extract-glossary`

**Risiko:** Jika server terpapar ke jaringan, siapapun bisa:
- Menulis file ke filesystem (via save-chapter / export-novel)
- Mengirim request ke OpenRouter/Gemini (menghabiskan API quota)
- Membaca config termasuk API keys
- Menerjemahkan teks sembarangan (biaya token)

**Rekomendasi:** Tambah minimal session-based auth atau API key header validation.

---

### 5. Tidak Ada Rate Limiting

**File:** `server.ts` — tidak ada middleware rate-limit

Tidak ada pembatasan request per client/IP. Endpoint `/api/translate` yang memanggil LLM API bisa di-spam untuk menghabiskan quota/API key pemilik.

**Rekomendasi:** Gunakan `express-rate-limit` atau serupa.

## 🟠 TINGGI — Bug Fungsional & Risiko Data

### 6. Tidak Ada Input Validation/Sanitasi di Sisi Server

**File:** `server.ts` — semua endpoint POST

| Field | Sumber | Risiko |
|-------|--------|--------|
| `folder_path` | Request body | Path traversal (lihat #1) |
| `chapter_title` | Request body | Karakter invalid untuk filename Windows (`\ / : * ? " < > \|`) |
| `novel_title` | Request body | Sama — bisa merusak path |
| `teks_asli` / `teks_terjemahan` | Request body | Tidak ada batasan ukuran per-field (hanya limit 10mb untuk JSON body secara keseluruhan) |
| `chapter_number` | Request body | Tidak ada validasi tipe — string bisa dikirim |

**Rekomendasi:** Validasi dan sanitasi semua input di sisi server sebelum diproses atau ditulis ke disk.

---

### 7. File Overwrite Tanpa Konfirmasi atau Versioning

**File:** `server.ts` — baris 275

```ts
fs.writeFileSync(filePath, mdContent, 'utf-8');
```

`/api/save-chapter` akan menimpa file `Chapter_XX.md` yang sudah ada tanpa konfirmasi atau backup versi sebelumnya.

**Rekomendasi:** Tambahkan timestamp ke filename atau konfirmasi overwrite.

---

### 8. Tidak Ada Timeout pada Panggilan AI (LLM API)

**File:** `server.ts` — `callOpenRouter` (line 54–68), `callGeminiWithRetryAndFallback` (line 114–188)

Tidak ada `AbortController` atau timeout pada fetch request ke OpenRouter maupun Google Gemini API. Jika LLM API tidak responsif:
- Request hang tanpa batas waktu
- Connection pool terisi penuh
- Server menjadi tidak responsif untuk request lain

**Rekomendasi:** Tambah `AbortController` dengan timeout 30–60 detik pada setiap panggilan AI.

---

### 9. Tidak Ada CSP (Content Security Policy) Headers

**File:** `server.ts` — tidak ada middleware security headers

Tidak ada Content-Security-Policy, X-Content-Type-Options, X-Frame-Options, atau security header lainnya.

**Risiko:**
- **XSS:** Inline script atau eval() dari sumber eksternal bisa dieksekusi
- **Clickjacking:** App bisa di-frame oleh situs jahat
- **MIME sniffing:** Browser bisa salah interpretasi tipe konten

**Rekomendasi:** Gunakan middleware `helmet` untuk Express.

---

### 10. X-Powered-By Header Terpapar

**File:** `server.ts` — default Express behavior

Express menambahkan header `X-Powered-By: Express` yang mengungkapkan teknologi backend ke penyerang.

**Rekomendasi:** Nonaktifkan dengan `app.disable('x-powered-by')` atau gunakan `helmet`.

---

### 11. localStorage Tanpa Enkripsi

**File:** `src/services/storage.ts` — semua fungsi `getStored*`/`saveStored*`

Seluruh data pengguna (novel, chapters, references, glossaries, AI config) disimpan di `localStorage` browser dalam plaintext JSON:
```ts
localStorage.setItem(NOVELS_KEY, JSON.stringify(novels));
```

**Risiko:** Jika user mengakses dev tools atau ada XSS, seluruh data novel (termasuk teks asli dan terjemahan) bisa diekstrak.

---

### 12. Import File Tanpa Batasan Ukuran

**File:** `src/App.tsx` — baris 443–464

```ts
const handleImportChapterFile = (e: React.ChangeEvent<HTMLInputElement>) => {
  const file = e.target.files[0];
  const reader = new FileReader();
  reader.readAsText(file);
};
```

Tidak ada batasan ukuran file `.txt`/`.md` yang bisa di-import. File sangat besar (>100MB) bisa membekukan browser tab.

**Rekomendasi:** Tambah batasan ukuran file (mis. max 5MB) sebelum dibaca.

## 🟡 SEDANG — Bug Fungsional

### 13. Tidak Ada Cleanup URL Object (Memory Leak Potensial)

**File:** `src/services/exportZip.ts` — baris 62–70

```ts
const downloadUrl = URL.createObjectURL(content);
// ... trigger download ...
URL.revokeObjectURL(downloadUrl);
```

`revokeObjectURL` dipanggil di akhir, tetapi jika download gagal atau user menutup tab sebelum download selesai, object URL tidak di-release. Dalam praktiknya ini minor karena browser membersihkan saat tab ditutup, tapi bisa menyebabkan memory pressure pada sesi lama.

---

### 14. Memory Leak — dirHandles Map Tidak Dibersihkan

**File:** `src/services/fileSystemStorage.ts` — baris 4

```ts
const dirHandles = new Map<string, FileSystemDirectoryHandle>();
```

Map `dirHandles` tidak pernah dibersihkan. Entry untuk novel yang sudah dihapus tetap tersimpan di memory. Seiring waktu, ini bisa menambah memori yang tidak terpakai.

---

### 15. Hardcoded HTTP-Referer Header ke Domain Lain

**File:** `server.ts` — baris 37

```ts
'HTTP-Referer': 'https://ai.studio',
```

Header `HTTP-Referer` dikirim ke OpenRouter dengan domain `ai.studio` yang bukan domain aplikasi ini. Beberapa provider OpenRouter memvalidasi referer dan bisa memblokir atau membatasi request.

**Rekomendasi:** Ganti dengan domain yang benar atau hapus header ini jika tidak diperlukan.

---

### 16. Tidak Ada Fallback untuk AbortError pada Folder Picker

**File:** `src/services/fileSystemStorage.ts` — baris 21–26

```ts
if (error?.name !== 'AbortError') {
  console.error('Error selecting folder:', err);
  alert(`Gagal membuka folder picker: ${error?.message || 'Terjadi kesalahan'}`);
}
```

Ketika user membatalkan folder picker (AbortError), error hanya di-log ke console tanpa feedback visual ke user. User tidak tahu bahwa operasi dibatalkan.

---

### 17. Race Condition pada Auto-Save

**File:** `src/App.tsx` — baris 177–181

```ts
useEffect(() => {
  if (activeNovel && chapters.length > 0) {
    syncToLocalFS();
  }
}, [chapters, references, glossaries, synopsis, writingStyle]);
```

Setiap perubahan pada data triggers `syncToLocalFS()` yang memanggil `saveNovelToLocalFS`. Jika perubahan terjadi cepat berturut-turut (mis. user typing di editor), beberapa write bisa bertumpuk dan menimpa data yang lebih baru.

---

### 18. Tidak Ada Validasi Model ID di Sisi Server

**File:** `server.ts` — baris 42, 450

Model ID dikirim langsung dari client ke provider API tanpa validasi:
```ts
const model = ai_config?.model || (provider === 'openrouter' ? 'google/gemini-2.5-flash' : 'gemini-2.5-flash');
```

User bisa memasukkan model ID sembarangan yang tidak valid, menghasilkan error 400 dari provider tanpa pesan yang helpful.

## 🟢 RENDAH — Minor / Cosmetic


Pola `.env*` sudah ada dan `!.env.example` sudah dikecualikan. Ini sudah benar, tapi perlu dipastikan file `.env` yang berisi API key sebenarnya tidak ada di repo.

### 20. Tidak Ada `helmet` Middleware

**File:** `server.ts` — tidak ada

Express tidak menggunakan `helmet` untuk security headers.

---

### 21. `requestFramePermissions` Kosong di metadata.json

**File:** `metadata.json` — baris 4

```json
"requestFramePermissions": []
```

Tidak ada permission yang diminta, yang bisa jadi masalah jika app di-deploy sebagai PWA atau di dalam frame.

---

### 22. Tidak Ada React Error Boundary

**File:** `src/App.tsx` — tidak ada Error Boundary

Jika komponen React crash (mis. karena data tidak valid), seluruh aplikasi menampilkan layar putih tanpa graceful degradation.

---

### 23. `Math.random()` untuk ID Generator — Tidak Cryptographically Secure

**File:** `src/App.tsx` — baris 494, 630

```ts
id: `glos-${Date.now()}-${Math.random().toString(36).substr(2, 4)}`
```

`Math.random()` tidak cryptographically secure. Untuk ID internal tidak kritis, tapi sebaiknya gunakan `crypto.randomUUID()` atau `crypto.getRandomValues()` untuk ID yang terpapar ke user.

## 💡 REKOMENDASI PRIORITAS

### Prioritas 1 (Segera)
1. **Path traversal fix** — Validasi `folder_path` agar hanya bisa di dalam direktori yang diizinkan.
2. **Jangan kirim API key ke client** — Hanya kirim `default_provider` dan `default_model` ke client.
3. **Tambah autentikasi minimal** — Minimal session-based atau API key header validation.
4. **Bind ke 127.0.0.1** — Ganti `0.0.0.0` ke `127.0.0.1`.

### Prioritas 2 (Mendatang)
5. **Tambah rate limiting** — Gunakan `express-rate-limit`.
6. **Tambah timeout pada AI calls** — AbortController dengan timeout 30–60 detik.
7. **Tambah security headers** — Gunakan `helmet` middleware.
8. **Sanitasi filename** — Bersihkan `chapter_title` dan `novel_title` sebelum ditulis ke disk.

### Prioritas 3 (Nice to Have)
9. **Tambah React Error Boundary**
10. **Tambah batasan ukuran file import**
11. **Cleanup dirHandles Map**
12. **Gunakan crypto.randomUUID() untuk ID**
